Run a server

haulnet-server runs LuxonServer, an open-source Photon-compatible server, with a ready config for R.E.P.O. and a small status endpoint. Keep it private and share the address, or add it to the public list.

Private or public?

The same package serves two very different purposes. Decide first which one you want.

For you and your friends

A server at home, at a LAN party or on a VPS that only your group uses. Share its address; friends pick it with + Server by address. It is yours: turn it off whenever you like, nobody else depends on it. No listing and no rules. (To host a single game on your own PC you need no server at all: use On my PC.)

For everyone: the public list

A listed server appears in every player's game as part of a city row, and Haulnet sends other people's games to it. That is a commitment: it must stay online around the clock on a stable public address, stay updated, and its operator answers reports. The Haulnet monitor checks it every minute, opens an issue after an hour offline, ranks it lower in its city after outages, and a server unreachable for a week may be removed.

Requirements

  • Linux x86-64 (Docker or plain systemd) or Windows x64.
  • A public IPv4 address; UDP not filtered by the provider. IPv6 works too, but an IPv6-only server is not enough: most players have no IPv6 (in Russia about nine in ten).
  • Bandwidth: roughly 2–4 Mbit/s outgoing per 6-player game; an unmetered port of 100 Mbit/s or more and DDoS protection that covers UDP are recommended for public servers.
  • CPU and memory are modest: LuxonServer is a single-threaded C++ program.

Ports

Players connect to 27000 first; the server then hands them 27001 and 27002.

PortProtocolPurposeOpen to players
27000UDPNameServer (first contact)yes
27001UDPMasterServer (lobby)yes
27002UDPGameServer (the game itself)yes
27080TCPStatus endpoint (/status, /healthz)yes, for server choice
5088TCPLuxonServer's web API, loopback onlynever

LuxonServer's own web API has no authentication and shows player addresses, user IDs and tokens. haulnet-server always binds it to 127.0.0.1: never publish or forward port 5088.

Docker

Install Docker Engine with its compose plugin first. The commands below use sudo; as root, leave it out.

mkdir haulnet-server && cd haulnet-server
base=https://github.com/haulnet/haulnet-server/releases/latest/download
curl -fsSLO "$base/docker-compose.yml"
curl -fsSLO "$base/haulnet-update" && chmod +x haulnet-update
curl -fsSL -o haulnet-server.env "$base/haulnet-server.env.example"
nano haulnet-server.env        # set EXTERNAL_ADDRESS
docker compose up -d
docker compose logs -f

The compose file uses host networking and the image ghcr.io/haulnet/haulnet-server:latest. To stay on one release, put its version without the v, for example HAULNET_SERVER_TAG=0.1.4, into a file named .env next to docker-compose.yml. If the server has a firewall, open the ports, for example with ufw:

sudo ufw allow 27000:27002/udp
sudo ufw allow 27080/tcp

Without Docker

  • Linux with systemd: download haulnet-server-version-linux-x86_64.tar.gz and SHA256SUMS from the latest release and check the file with sha256sum --ignore-missing -c SHA256SUMS. The tarball has haulnetd, luxon_server and a systemd unit that runs as a dynamic unprivileged user on a read-only system. Install steps: README.
  • Windows: unzip the release zip, run start.bat once (it creates haulnet-server.env), set EXTERNAL_ADDRESS there and run start.bat again. Allow luxon_server.exe (UDP) and haulnetd.exe (TCP 27080) in Windows Firewall. Stop the server by closing its console window.

Main settings

Environment variables, or KEY=VALUE lines in haulnet-server.env:

VariableDefaultMeaning
EXTERNAL_ADDRESS— (required)Public IP or DNS name players use to reach this server. No port, no scheme.
SERVER_NAMEhaulnet-serverName in the status endpoint and logs.
MAX_ROOMS, MAX_PLAYERSnot setSoft limits: Haulnet starts no new games here when reached.
MAX_CONNECTIONS600Hard limit enforced by LuxonServer (a player uses about two: game and voice).
STATUS_ADDRESS:27080Where the status endpoint listens.
STATS_LOG_INTERVALoffLog rooms, players, traffic and CPU load every interval of at least 10 s, e.g. 60s.

Updating

Each release pins one LuxonServer version. When R.E.P.O. changes its Photon version, a new release follows; an old server is then no longer chosen for its city and servers.haulnet.cc marks it Incompatible, so keep it updated. With Docker, haulnet-update does it safely:

sudo ./haulnet-update enable     # automatic updates every 10 minutes (recommended)
sudo ./haulnet-update status     # on/off, running version, last result
sudo ./haulnet-update            # one check now
sudo ./haulnet-update rollback   # back to the version before the last update
sudo ./haulnet-update disable

An update installs only on an empty server. If players are on, the server drains: it starts no new games (its status says "accepting": false, "draining": true) while running games go on, and the next check installs the update once the server is empty. After a single run by hand, run it again later (or enable automatic updates): until the update is installed, the server takes no new games. If the new version does not come up within 90 seconds, the previous one starts again.

Options in haulnet-server.env: UPDATE_WINDOW=03:00-07:00 allows updates only at those hours; UPDATE_FORCE_AFTER=3h installs anyway after waiting that long, and sudo ./haulnet-update --force installs right now (both disconnect the players still on). Without Docker, replace haulnetd and luxon_server with the ones from the new release and restart the service. Details: Updating.

Status endpoint

curl http://<server>:27080/status

It publishes counts and versions only (name, rooms, players, limits, CPU load, accepting, draining, uptime), never room names, player names, addresses or IDs. Haulnet uses it to pick a server; the server list page shows it live.

Privacy

Like any game server, yours sees the IP addresses of connecting players, and LuxonServer's log also contains player IP addresses, Steam IDs and room names. Keep logs only as long as you need them and do not publish them.

Add it to the public list

Only for a server that is meant to be public (see above). Before you apply, make sure you have:

  • a machine that runs around the clock: a VPS or a dedicated server, not a home PC that sleeps or a connection that drops at night;
  • a stable public IPv4 address or DNS name, and bandwidth for the games you allow (MAX_ROOMS, MAX_PLAYERS);
  • automatic updates on (sudo ./haulnet-update enable) or a habit of updating soon after each release;
  • a GitHub account whose notifications you read: problems with your server arrive there as issues.
  1. Bring the server up and check /status from another machine.
  2. Fork haulnet-servers and add one file servers/<region>/<city>-<N>.json, following its guide; add your city to data/locations.json if it is not there. The name, like Europe [Moscow] #1, is derived from the city and number.
  3. Open a pull request. CI checks the entry, its DNS and the status endpoint; a maintainer reviews and merges it. Within minutes the mod and servers.haulnet.cc show it, and the Haulnet monitor checks it once a minute.

Rules for operators, in short (full text in the list's README): run the official package and keep it updated; keep it online around the clock on a stable address (a server unreachable for a week may be removed); answer reports through the GitHub account in your entry; never inspect or sell players' traffic; no ads, payments or accounts for players. Everything in an entry is public.
